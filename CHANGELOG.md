## 0.85.1 — 2026-10-06

### Changed

- **Exports that return Elysia apps or plugins carry Elysia 2.0.0-beta.21's types** (`agentAuthContextPlugin`, `agentAuthPlugin`, `apiKeysRoutes`, `auth`, `complianceRoutes`, `createAuthApplications`, `createAuthContext`, `createAuthHtmxRoutes`, `createCredentialsApi`, `createSignoutApi`, `credentialRoutes`, `credentialsEmailVerification`, `credentialsLogin`, `credentialsPasswordReset`, `credentialsRegister`, `mfaChallenge`, `mfaManagementRoutes`, `mfaRoutes`, `mfaSmsRoutes`, `mfaTotpRoutes`, `nativePushRoutes`, `oidcProviderRoutes`, `oidcSsoRoutes`, `organizationRoutes`, `passwordlessRoutes`, `portalRoutes`, `protectPermissionPlugin`, `protectRoutePlugin`, `pushRoutes`, `requireAuthPlugin`, `roleRoutes`, `samlIdpRoutes`, `samlSsoRoutes`, `scimRoutes`, `sessionCleanup`, `sessionRoutes`, `sessionStore`, `ssoDiscoveryRoute`, `statusListRoutes`, `stepUpPlugin`, `vciRoutes`, `vpRoutes`, `webauthnRoutes`)
  These exports return Elysia apps, plugins or route handlers, so their generated declarations now inline Elysia 2.0.0-beta.21's context types (its `status()` signature, `set.redirect` typed as `never`, and type references from `elysia` instead of `elysia/types`), because the package is now built against that Elysia. Their parameters and behavior are unchanged; they type-check against both 2.0.0-beta.6 and 2.0.0-beta.21.

### Fixed

- **Auth callbacks can return `status(...)` on Elysia 2.0.0-beta.21** (`StatusReturn`)
  `StatusReturn` picked `code` from Elysia's `ElysiaStatus`, which Elysia 2.0.0-beta.21 removed (the status box now carries `status` and `response`). Every `status(...)` returned from an auth callback (`onCallbackSuccess`, `getUser`, `onNewUser`, `onLinkConnector`, `onLinkIdentity`) was a type error on that Elysia. `StatusReturn` now picks `status` and `response`, which every Elysia 2 beta has, so it works on 2.0.0-beta.6 and beta.21 alike. Runtime behavior is unchanged: `isStatusResponse` already detected a status box by `status`.

## 0.79.0 — 2026-09-10

### Breaking

- **Separate API credential token routes from OIDC and reject conflicting configuration** (`apiKeysRoutes`, `auth`, `createAuthApplications`, `AuthConfig`, `ApiKeysConfig`)
  _Migration:_ Send client_credentials requests to /auth/api/token instead of /oauth2/token and update advertised enterprise token URLs. Keep authorization_code and refresh_token requests at /oauth2/token. Prefer auth({ oidc, apikeys }) for configuration validation. API-only consumers may explicitly keep tokenRoute: /oauth2/token if no OIDC handler uses that path.
