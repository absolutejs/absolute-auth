## 0.88.0 — 2026-09-24

### Added

- **Add encrypted interactive-transaction OAuth credential coordination; serialize refresh and removal with grant row locks, persist recovery before returning failures, and reject stale or forged credential handles. Bound ambiguous token renewals and require reconnection after permanent failures.** (`createCoordinatedOAuthLinkedProviderCredentialResolver`)

## 0.87.1 — 2026-09-24

### Fixed

- **Declare session and linking cookies on the OAuth authorization route so opt-in session binding accepts existing signed-in users. Add an authorization-start regression test.** (`createAuthApplications`)

## 0.87.0 — 2026-09-24

### Added

- **Add owner-bound encrypted linked-provider grant storage, session-bound OAuth linking, and an exported OAuth authorization resolver for separately consented connectors.** (`createEncryptedLinkedProviderGrantStore`, `resolveOAuthAuthorization`, `AuthConfig`, `createAuthApplications`)

## 0.86.1 — 2026-09-23

### Fixed

- **Allow authorized nonmember organization managers to list memberships. Revoke invitations when their delivery hook fails and return a sanitized retryable error.** (`organizationRoutes`, `createAuthApplications`)

## 0.86.0 — 2026-09-23

### Breaking

- **Bind organization invitation acceptance to a verified email and atomically consume the invitation with membership creation. Deny expired, revoked, missing-organization and suspended-member invitations; preserve existing member roles.** (`acceptInvitation`, `OrganizationsConfig`, `OrganizationStore`, `listUserOrganizations`, `organizationRoutes`)
  _Migration:_ Configure organizations.getVerifiedEmail with provider-verified email evidence. Direct acceptInvitation callers must supply verifiedEmail. Custom OrganizationStore adapters must implement atomic acceptInvitation; older adapters fail closed.

## 0.85.0 — 2026-09-23

### Breaking

- **Use the native Citra Neon provider for Auth configuration and linked-account refresh** (`createNeonProviderConfiguration`, `neonProviderConfiguration`)
  _Migration:_ Move createNeonProviderConfiguration results from customProviders.neon to providersConfiguration.neon. Neon is now a built-in Citra provider; credentials, scopes and offlineAccess inputs are unchanged.

### Changed

- **Include Neon in the typed built-in provider registry and configuration resolution** (`buildClientProviders`, `resolveProviderClientConfiguration`)

## 0.79.0 — 2026-09-10

### Breaking

- **Separate API credential token routes from OIDC and reject conflicting configuration** (`apiKeysRoutes`, `auth`, `createAuthApplications`, `AuthConfig`, `ApiKeysConfig`)
  _Migration:_ Send client_credentials requests to /auth/api/token instead of /oauth2/token and update advertised enterprise token URLs.
